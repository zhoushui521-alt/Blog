## 本地运行

需要 Node.js 22.x（运行时）和 Bun 1.3.10（依赖管理与脚本工具）。

```sh
# 获取项目
git clone https://github.com/zhoushui521-alt/Blog.git
cd Blog

# 按锁文件安装依赖
bun install --frozen-lockfile

# 启动开发预览，以终端显示的地址为准
bun dev
```

常用检查：

```sh
bun run check          # 检查类型和内容格式
bun test               # 运行已有测试
bun run build          # 生成生产构建
bun run build:checked  # 先检查，再构建
```

## 写文章

文章放在 `src/content/blog/`（文章目录）。一篇文章一个文件夹，正文使用 Markdown / MDX（标记文本格式），配图放在同一文件夹中。

例如 `src/content/blog/20261003-learning-with-ai/post.md`（首篇文章文件）：

```markdown
---
title: '文章标题'
description: '用一两句话说明这篇文章讨论什么。'
publishDate: 2026-10-03
tags: ['学习记录']
language: 'zh'
draft: false
comment: false
---

从正文开始。页面会自动显示标题，不需要再写一个一级标题。

## 第一个小节

正文内容。
```

- `draft: true`（草稿）用于尚未准备公开的文章；草稿标记不会阻止源码被上传到公开仓库，私人草稿请留在笔记库或仓库之外。
- `draft: false`（已发布）让文章进入正式列表、搜索和订阅源。
- 标题最多 60 个字符，摘要最多 160 个字符；正文里的二级、三级标题会生成目录。
- 延伸阅读只放与正文直接相关、实际引用的资料；单纯的文风参考不列入。
- 如需英文版，在同目录新增 `post.en.md`（英文正文），设置 `language: 'en'`（英文）及 `translationKey`（对应中文文章的路径）。例如首篇文章的对应值为 `20261003-learning-with-ai/post`。

## 写笔记

笔记放在 `src/content/notes/`（笔记目录），围绕具体问题解释概念、例子、适用边界和待验证内容，不用项目发布记录充当学习笔记。

从个人笔记库选材时，只整理确认能公开的正文；原始笔记、私人路径、聊天记录、追踪参数和未经核实的效果数字不随仓库上传。引用资料放在对应论述旁边，文风参考不列为延伸阅读。

目前整理了四个主题：[检索与上下文](src/content/notes/rag-retrieval-ranking-context.md)、[链式数据流](src/content/notes/lcel-data-flow.md)、[数据驱动界面](src/content/notes/react-data-driven-ui.md)、[任务交接](src/content/notes/context-handoff.md)，各有对应英文版。页面日期为公开整理日期，原始记录日期在已知时单独注明。

## 部署

从 Vercel（托管平台）导入本仓库，选择 Astro（框架预设）、仓库根目录和 Node.js 22（运行时），生产分支使用 `main`（主分支）。安装与构建命令已在 `vercel.json`（部署配置）中定义。

站点地址优先读取 `PUBLIC_SITE_URL`（公开站点地址），例如未来实际分配的默认域名或自有域名。未设置时，使用平台提供的正式域名；本地开发回退到本地地址。部署后应确认文章地址、分享图片、站点地图和订阅源都指向最终域名。

当前公开内容不需要数据库、机器人或评论服务密钥。评论保持关闭；文章底部的支持入口已接入自己的微信收款二维码，图片可直接查看和保存。

## 更新方式

**完成并确认的博客更新，需要同步到 GitHub（远端仓库），不能只留在本地。**

- 文章发布、内容修改和日常小问题：沟通确认后直接提交并推送到主分支，不额外创建 Issue（议题）或 PR（拉取请求）。
- 较大的功能、设计或交互改进：先通过议题明确问题和预期效果，在独立分支实现、推送并提交拉取请求，确认后合并。
- 按改动影响完成必要检查。文章修改重点检查正文、链接和页面显示；功能改动补充对应测试与构建验证。
- 同步代码与发布网站是两件事。连接托管平台的自动部署后，主分支更新才会按平台配置触发网站发布。

## 隐私与公开范围

这是公开仓库，只保存确认可以公开的源码、文章和素材。

`.gitignore`（忽略规则）已覆盖环境变量、私钥、证书、本地凭据、数据库、智能体配置、私人资料目录、依赖和构建产物。`.env.example`（环境配置样例）仅用于说明配置，不填写真实密钥。

私人笔记、原始聊天记录和未脱敏截图请放在仓库之外。放进 `public/`（公开资源目录）的文件会随网站直接公开；放进 `src/content/`（内容目录）的文件可能进入页面、搜索或订阅源。

忽略规则不能清除已提交的文件和历史。每次同步前仍需检查实际改动；二维码等个人素材也应确认公开范围后再上传。
